# 验证范围与已知限制

## 0.1.4

本版修复歌曲操作面板的生命周期与遥控交互。面板改为独立模态窗口，背景侧栏与播放器不能抢走焦点；选择动作后自动关闭，返回键／向左／右上关闭图标均可收起。切换页面会原子清除面板及其歌曲来源数据，避免残留到全屏播放页。

首项操作根据选中歌曲和实时播放状态显示「播放／暂停／继续播放」。当前歌曲提供直达「正在播放」的入口，进入后隐藏侧栏与迷你播放器。这里的暂停保留队列和进度。

新增设备按键回归覆盖面板左右边界、返回收起、选择后收起、播放状态实时变化、暂停／恢复不重建队列、面板内与外部导航的清理、全屏播放页没有侧栏。连同原有测试，共 12 个单元测试和 7 个设备整合测试。

## 0.1.3

应用曾在 Sony 电视上实际安装使用；本轮 0.1.3 的自动化、队列边界和效能测量使用 Android TV API 34 模拟器，1280×720。未据此宣称全部 Sony 型号、4K 输出或长期运行均已验证。

**11 个 JVM 单元测试、6 个设备整合测试通过。** 设备测试使用真实 ExoPlayer 与本机 HTTP 测试服务器。

| 范围 | 已验证 |
| --- | --- |
| 播放线程 | 背景线程发起播放回到播放器 main looper；修复首页随机播放崩溃 |
| 队列 | 1000 首跳转、自然播放跨过初始 300 首、队尾循环、上一首、插入／移除与连续加入 |
| 分页 | 所有歌曲使用后续 offset 100／200／300；随机来源取得下一批；旧请求不混入新来源 |
| 缓存 | 第二次封面请求命中内存；清除内存后命中磁盘，未重新下载；账号变化隔离缓存键 |
| 请求 | 专辑数据与歌曲共用 getAlbum；歌手最多 4 个请求并行 |
| 生命周期 | 三次建立、播放和停止服务后，服务拥有的协程均取消 |
| 更新范围 | 播放进度变化不重新发出低频 PlaybackState |
| 遥控操作 | 正式包进入播放页、开启／关闭模式选单、进度调整、恢复与暂停 |

原生播放器窗口最多 300 首，逻辑队列仍保存当前来源的完整歌曲 metadata，供队列浏览与任意跳转。封面缓存上限为内存 16 MiB、磁盘 64 MiB；页面状态最多 12 组，专辑数据缓存最多 32 笔、期限 5 分钟。

## 效能测量的边界

在同一模拟器播放同一首歌并显示歌曲列表，0.1.2 的程序 CPU 约占单核心 8.0%，0.1.3 为 8.62%，暖机后另一段为 8.45%。滚动后 PSS 约 82 MiB；本轮仍有偶发长帧，未以 Perfetto 定位原因。

这些短测没有证明整体 CPU 或帧时间下降，也不能单凭模拟器结果认定实机表现。已通过针对性测试确认的改动，是缓存命中、请求去重、主线程准备工作移除、服务清理和播放器窗口有界；仍需在实际电视上以相同操作和网络条件比较。

## 当前限制

- 未提供歌词、离线下载、电视文字搜索或手机遥控播放。
- 扫码配置要求手机可访问电视，模拟器 NAT 需要额外转发。
- 其他 Subsonic 兼容服务器尚未充分验证。
- 同一封面 ID 被覆盖后，可手动清除封面缓存更新。
- 大曲库 metadata 占用、慢网络与数小时真机播放仍需继续测试。
- 当前仓库构建配置使用本机 debug key 签名，跨开发电脑的安装包不保证能互相覆盖。
